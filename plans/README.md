## Dependency notes

- **002 requires 001.** 001 introduces the three new fields (`target_dpi`,
  `jpeg_quality`, `dpi_margin`) and converts the derived `Default` into a manual
  one. 002 then wraps that struct in a forward-compatible public API and rewrites
  the *same* call sites 001 touched (from struct literals to builder methods). Do
  not start 002 until 001 is DONE, or you will edit those call sites twice.

## Leverage / honest priorities

- **001 is the only must-do.** It is the functional prerequisite for a CLI or any
  consumer that needs to tune compression strength. Without it the optimizer's
  sweet spot is hardcoded and cannot be exposed.
- **002 is recommended for publication, but optional.** It is pure API-shape
  forward-compatibility so a *published* crate can gain options later without a
  breaking release. If the maintainer prefers plain `pub` fields and is willing
  to accept that every future field addition is a semver-major change, 002 can be
  skipped. It is included because the project's goal is a credible, idiomatic
  open-source crate.

## Explicitly out of scope (and why)

- **The `amatl` CLI binary itself.** It belongs in the standalone crate's own
  repository after extraction (roadmap Phase 1/2), not in this app's tree. These
  plans make the *library API* CLI-ready; they do not add a `main.rs`/arg parser.
- **Threading the new tunables through the desktop app's IPC + TS wrapper**
  (`amatl_optimize` in `lib.rs`, `amatl.optimize` in `pdf-utils.ts`). The desktop
  app deliberately ships a single measured sweet spot (130 DPI / Q78) and exposes
  no compression knobs to end users — see `src-tauri/src/AGENTS.md`. Adding UI
  knobs would be a product decision, not a refactor, and is not required for
  extraction. 001 keeps the app's behavior byte-identical by leaving its IPC call
  on the defaults.

## Findings considered and rejected

- **Validate option values in a constructor / `TryFrom`**: rejected in favor of
  defensive clamping at the point of use (folded into 001). The optimizer's core
  contract is fail-safe (never panic, never produce a worse-than-input file); a
  bad option value must degrade gracefully wherever it is read, not require
  callers to route through a fallible constructor. Clamping at use keeps the
  `Copy` + `Default` ergonomics and the fail-safe guarantee in one place.
- **Make the option fields private**: rejected. `#[non_exhaustive]` (002) already
  prevents external struct-literal construction; keeping fields `pub` for
  *reading* is useful (e.g. a CLI echoing its effective config) and costs nothing.
