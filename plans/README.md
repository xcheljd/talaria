## Findings considered and rejected

(So nobody re-audits them.)

- **"Email HTML regenerates on every keystroke" (perf)** — rejected. The
  page-level `emailHTML` memo (`PromotionPage.tsx:87`) subscribes via `useShallow`
  to exactly `selectEmailDataSource` (email-affecting fields) plus two stable fn
  refs; collapse/bulk-recipient changes do not trigger regeneration. Already
  correctly memoized; the code comment documents it.
- **"Unawaited `saveToIndexedDB` loses errors" (correctness)** — downgraded /
  not worth a plan. `saveToIndexedDB` catches internally and drives the existing
  global `saveStatus` warning toast, so the missing `await` costs essentially
  nothing.
- **"iframe `allow-same-origin` enables exfiltration" (security)** — rejected.
  The preview iframe has no `allow-scripts`, so framed content cannot execute JS
  regardless; combined with the strict CSP, this is not a vulnerability.
- **"`@tiptap/extension-blockquote` is a dead dependency" (tech-debt)** —
  rejected. Blockquote is actively used (`NewsletterToolbar.tsx:404`,
  `extensions.ts:92`); at most the explicit package duplicates StarterKit. Not
  worth churn.
- **`generateId` collision (correctness)** — not planned. Requires >1000 ID
  generations within a single millisecond; only plausibly reachable via a huge
  synchronous config import. Narrow; the author already reasoned about the
  wrap-around in a comment. Revisit only if bulk import grows.
- **God-module / newsletter-duplication refactors (tech-debt)** — not planned.
  L-effort, HIGH-risk refactors across 40+ consumers; the team already did
  targeted split passes. Low leverage vs. risk right now.
- **TipTap minor lag 3.22→3.26, no pre-commit hooks (deps/dx)** — noted, not
  planned. Hygiene-only; CI already enforces the gates a pre-commit hook would.
